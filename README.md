# MS Woodworks

موقع عربي لعرض أعمال MS Woodworks واستقبال طلبات العملاء، مع لوحة إدارة خاصة لمتابعة الطلبات والتعليقات والعاملين.

## المتطلبات

- Docker Desktop مع Docker Compose، أو Node.js 24 وقاعدة بيانات PostgreSQL.
- ملف إعدادات خاص `.env` يحوي بيانات دخول الإدارة وأسرار الجلسة وقاعدة البيانات. لا تشارك هذا الملف ولا ترفعه إلى Git.

## التشغيل باستخدام Docker على Windows

1. انسخ `.env.example` إلى `.env`.
2. عيّن `POSTGRES_PASSWORD` إلى كلمة مرور قوية وفريدة، و`ADMIN_EMAIL` و`ADMIN_PASSWORD` إلى بيانات إدارة آمنة. يجب أن تكون كلمة مرور الإدارة 14 حرفًا على الأقل، و`SESSION_SECRET` قيمة عشوائية لا تقل عن 32 حرفًا.
3. من PowerShell داخل مجلد المشروع نفّذ:

   ```powershell
   docker compose up --build -d
   docker compose logs -f app
   ```

4. افتح `http://localhost:3000` للموقع أو `http://localhost:3000/admin` للوحة الإدارة.

لإيقاف الخدمات مع الاحتفاظ ببيانات الطلبات استخدم `docker compose down`. لا تحذف volume `mswood-data` إذا كنت تحتاج إلى الاحتفاظ ببيانات PostgreSQL.

## التشغيل المحلي دون Docker

ثبّت Node.js 24 وPostgreSQL، أنشئ قاعدة بيانات `mswood`، ثم اضبط `DATABASE_URL` و`ADMIN_EMAIL` و`ADMIN_PASSWORD` و`SESSION_SECRET` في `.env`. بعد ذلك نفّذ:

```powershell
npm install
npm start
```

يُنشئ الخادم جداول حسابات العملاء والطلبات والتعليقات والعاملين والحضور والسُلف والجلسات عند بدء التشغيل. لا تفتح ملفات HTML مباشرةً من `file://`؛ شغّل الخادم لكي تعمل النماذج والحسابات ولوحة الإدارة.

لتشغيل اختبارات الخادم ولوحة الإدارة محليًا:

```powershell
npm test
```

لإضافة عاملين وفئات وسجلات حضور وسُلفة وأربعة طلبات **تجريبية فقط** إلى قاعدة البيانات المحلية، شغّل الخادم أولًا ثم نفّذ `npm run seed:demo`. يتطلب الأمر موافقة صريحة داخل الأمر، ويستخدم أسماءً موسومة بأنها تجريبية وأرقامًا نائبة، ولا يعمل في وضع الإنتاج. تشغيله مرة أخرى لا يكرر سجلات العرض.

## حسابات العملاء ولوحة الإدارة

1. يسجل العميل حسابًا مستقلًا من زر **دخول العملاء** باستخدام الاسم والبريد والهاتف وكلمة مرور من 10 أحرف على الأقل، أو يسجل الدخول ببريده وكلمة مروره. لا يتطلب التسجيل تفعيل البريد حاليًا.
2. من الحساب يمكن للعميل رؤية الطلبات التي أرسلها أثناء تسجيل الدخول فقط. يظل إرسال الطلب متاحًا للزوار، والطلبات القديمة غير المرتبطة بحساب لا تظهر في سجل العميل.
3. تعرض لوحة الإدارة قائمة حسابات العملاء المسجلة وبيانات التواصل وتاريخ التسجيل. كلمات المرور مشفّرة ولا تُعرض أو تُحفظ بصيغة مقروءة.
4. لإدارة الموقع افتح `/admin` وسجّل الدخول ببيانات `ADMIN_EMAIL` و`ADMIN_PASSWORD` من Vercel أو `.env`. بيانات الإدارة منفصلة عن حسابات العملاء، ولا توجد كلمة مرور افتراضية.
5. من تبويب **الطلبات** راجع رسائل العملاء، وابحث بالاسم أو الهاتف، واستخدم التصفية أو قائمة الحالة لتحديث الطلب: جديد، تم التواصل، قيد التنفيذ، مكتمل، أو ملغي.
6. من تبويب **تعليقات الصور** راجع التعليقات المعلّقة، ثم اختر اعتماد ونشر أو رفض. التعليقات المعتمدة فقط تظهر للعامة بجانب صورة المعرض وفي قسم آراء العملاء أسفل المعرض.
7. من تبويب **العاملون** أضف فئات العمل والعاملين وحدد لكل عامل راتبًا شهريًا ثابتًا. سجّل الحضور والانصراف يوميًا، أو حدّث سجل اليوم لإضافة وقت الانصراف لاحقًا. سجّل السُلف بتاريخها؛ تُخصم من راتب شهر صرفها. الحضور للمتابعة ولا يخصم تلقائيًا من الراتب.
8. من تبويب **المصروفات والعُهد** سجّل المسؤول والمبلغ عند تسليم عُهدة، وسجّل أي زيادة أو مبلغ مرتجع كحركة مستقلة. عند تسجيل مصروف اختر العُهدة ليُخصم المبلغ تلقائيًا، أو اختر مصروفًا مباشرًا خارج العُهد؛ لا يقبل النظام مصروف عُهدة يتجاوز الرصيد المتاح. أضف بند المصروف ووصفه والمورّد/المستلم وطريقة الدفع ورقم الإيصال والملاحظات عند توفرها.
9. اختر تاريخ البداية والنهاية لمراجعة إجمالي المصروفات، ومجموع ما صُرف من العُهد وخارجها، والمتبقي الحالي في جميع العُهد، والتجميع حسب بند الصرف وسجل الحركات. تُسجل المبالغ بالعملة المحلية (جنيه مصري). إجمالي المصروفات لا يحتسب تسليم العُهدة كمصروف؛ المصروف يُحتسب عند تسجيل الشراء أو الدفع نفسه فقط.
10. استخدم **تسجيل الخروج** عند الانتهاء. تنتهي جلسة الدخول تلقائيًا بعد 8 ساعات.

صفحة الإدارة تعرض ملخصًا للطلبات والتعليقات وتحتاج اتصالًا بخادم API وقاعدة PostgreSQL؛ عرض ملفات الموقع وحده لا يفعّلها.

## الوظائف

- معرض صور بتوزيع متجاوب، وتعليقات وآراء عملاء لا تظهر للعامة قبل اعتمادها من الإدارة.
- نموذج طلب يتصل بالخادم ويحفظ البيانات في PostgreSQL.
- حسابات عملاء مستقلة بكلمات مرور مشفّرة وسجل خاص بالطلبات المرتبطة بالحساب؛ يظل إرسال الطلبات كضيف متاحًا.
- لوحة إدارة محمية لتغيير حالة الطلبات واعتماد التعليقات أو رفضها.
- إدارة فئات العمل والعاملين، وتعديل بياناتهم أو إيقافهم مع الاحتفاظ بالسجلات التاريخية.
- تسجيل الحضور والانصراف والسُلف، وكشف شهري يحسب صافي الراتب بعد خصم السُلف المسجلة في الشهر نفسه.
- سجل مالي للعُهد والمصروفات المباشرة، يشمل تسليم الأموال والزيادات والمرتجعات، منع تجاوز رصيد العُهدة، وتقارير بإجمالي الفترة ومجموع المصروفات حسب المصدر والبند.
- حدود للمحاولات، وإعدادات جلسات آمنة، وحماية لمدخلات API.

## إضافة صور جديدة للمعرض

تُدار بيانات الصور ومعرّفاتها مرة واحدة في `public/gallery-assets.js` حتى يستخدم الموقع ولوحة الإدارة المسارات والعناوين نفسها. لإضافة صورة، ضع الملف في `public/img/` وأضف لها معرّفًا فريدًا واسمًا بديلًا صادقًا؛ اجعل `featured` بقيمة `true` لإظهارها في المعرض ونموذج آراء العملاء. احتفظ بالمعرّفات القديمة حتى تظل التعليقات المحفوظة مرتبطة بصورها في لوحة الإدارة، ولا تعرض ملصقًا أو شعارًا على أنه صورة مشروع.

## النشر على Vercel

تُقدّم ملفات `public/` الثابتة عبر Vercel، ويشغّل Vercel تطبيق Express المصدّر من `server.js` لمعالجة الموقع وطلبات `/api/*` معًا. يعيد المسار `/admin` كتابة صفحة `admin.html`. اترك Framework على Express وBuild Command وOutput Directory على القيم الافتراضية، وتأكد من عدم وجود إعداد نشر قديم يحصر البناء في `index.html` فقط. قبل أول طلب للـAPI:

1. اربط مستودع GitHub بمشروع Vercel واجعل مجلد المشروع هو Root Directory. استخدم إعداد إطار **Express** أو الاكتشاف التلقائي، ولا تضبط Output Directory على `public`؛ اترك Build Command وOutput Directory على القيم الافتراضية.
2. جهّز قاعدة PostgreSQL مُدارة ومتاحة من Vercel، ثم أضف هذه المتغيرات في Vercel: افتح **Project → Settings → Environment Variables** وأضف القيم لكل من Production وPreview عند الحاجة:
   - `DATABASE_URL`: رابط اتصال PostgreSQL؛ استخدم رابطًا مجمّعًا (pooled) إذا كان مزود قاعدة البيانات يوفّره.
   - `ADMIN_EMAIL`: بريد دخول الإدارة.
   - `ADMIN_PASSWORD`: كلمة مرور قوية وفريدة بطول 14 حرفًا على الأقل.
   - `SESSION_SECRET`: قيمة عشوائية سرية لا تقل عن 32 حرفًا.
   - `PGSSL`: اضبطها على `true` فقط إذا كان مزود قاعدة البيانات يتطلب TLS.
3. أعد النشر بعد حفظ المتغيرات. افتح `/` للموقع و`/admin` للإدارة.

نجاح البناء وحده لا ينشئ قاعدة البيانات أو هذه الأسرار؛ من دون إعدادها لن تعمل الطلبات والتعليقات وتسجيل دخول الإدارة. لا تضع الأسرار في `vercel.json` أو ملفات الواجهة أو Git. راجع [ADMIN-SETUP.md](./ADMIN-SETUP.md) لإعداد الإنتاج والنسخ الاحتياطي.

## GitHub Pages

يوجد سير عمل GitHub Pages ينشر واجهة الموقع من `public/` ويجهّز صفحة الإدارة على `/admin/`. GitHub Pages يستضيف ملفات ثابتة فقط ولا يشغّل Express أو قاعدة PostgreSQL؛ لذلك يعرض صفحة الدخول لكنه لا يستطيع تسجيل الدخول أو حفظ الطلبات. لتشغيل الإدارة والنماذج استخدم نشر Vercel أعلاه، واضبط متغيرات قاعدة البيانات والأسرار على المشروع نفسه.
