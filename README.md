# MS Woodworks

موقع عربي لعرض أعمال MS Woodworks واستقبال طلبات العملاء، مع لوحة إدارة خاصة لمتابعة الطلبات ومراجعة تعليقات المعرض.

## المتطلبات

- Docker Desktop مع Docker Compose، أو Node.js 24 وقاعدة بيانات PostgreSQL.
- ملف إعدادات خاص `.env` يحوي بيانات دخول الإدارة وأسرار الجلسة وقاعدة البيانات. لا تشارك هذا الملف ولا ترفعه إلى Git.

## التشغيل باستخدام Docker على Windows

1. انسخ `.env.example` إلى `.env`.
2. عيّن `POSTGRES_PASSWORD` إلى كلمة مرور قوية وفريدة، و`ADMIN_EMAIL` و`ADMIN_PASSWORD` إلى بيانات إدارة آمنة. يجب أن تكون كلمة مرور الإدارة 14 حرفًا على الأقل، و`SESSION_SECRET` قيمة عشوائية لا تقل عن 32 حرفًا.
3. من PowerShell داخل مجلد المشروع نفّذ:

   ```powershell
   docker compose up --build -d
   docker compose logs -f app
   ```

4. افتح `http://localhost:3000` للموقع أو `http://localhost:3000/admin` للوحة الإدارة.

لإيقاف الخدمات مع الاحتفاظ ببيانات الطلبات استخدم `docker compose down`. لا تحذف volume `mswood-data` إذا كنت تحتاج إلى الاحتفاظ ببيانات PostgreSQL.

## التشغيل المحلي دون Docker

ثبّت Node.js 24 وPostgreSQL، أنشئ قاعدة بيانات `mswood`، ثم اضبط `DATABASE_URL` و`ADMIN_EMAIL` و`ADMIN_PASSWORD` و`SESSION_SECRET` في `.env`. بعد ذلك نفّذ:

```powershell
npm install
npm start
```

يُنشئ الخادم جداول الطلبات والتعليقات والجلسات عند بدء التشغيل. لا تفتح ملفات HTML مباشرةً من `file://`؛ شغّل الخادم لكي تعمل النماذج ولوحة الإدارة.

لتشغيل اختبارات الخادم ولوحة الإدارة محليًا:

```powershell
npm test
```

## استخدام لوحة الإدارة

1. بعد ضبط متغيرات البيئة وتشغيل الموقع، افتح `https://اسم-موقعك.vercel.app/admin`، أو `http://localhost:3000/admin` محليًا.
2. سجّل الدخول باستخدام `ADMIN_EMAIL` و`ADMIN_PASSWORD` اللذين أعددتهما في Vercel أو `.env`. لا توجد كلمة مرور افتراضية ولا يلزم إنشاء حساب يدوي.
3. من تبويب **الطلبات** راجع رسائل العملاء، وابحث بالاسم أو الهاتف، واستخدم التصفية أو قائمة الحالة لتحديث الطلب: جديد، تم التواصل، قيد التنفيذ، مكتمل، أو ملغي.
4. من تبويب **تعليقات الصور** راجع التعليقات المعلّقة، ثم اختر اعتماد ونشر أو رفض. التعليقات المعتمدة فقط تظهر للعامة بجانب صورة المعرض.
5. استخدم **تسجيل الخروج** عند الانتهاء. تنتهي جلسة الدخول تلقائيًا بعد 8 ساعات.

صفحة الإدارة تعرض ملخصًا للطلبات والتعليقات وتحتاج اتصالًا بخادم API وقاعدة PostgreSQL؛ عرض ملفات الموقع وحده لا يفعّلها.

## الوظائف

- معرض صور وتعليقات لا تظهر للعامة قبل اعتمادها من الإدارة.
- نموذج طلب يتصل بالخادم ويحفظ البيانات في PostgreSQL.
- لوحة إدارة محمية لتغيير حالة الطلبات واعتماد التعليقات أو رفضها.
- حدود للمحاولات، وإعدادات جلسات آمنة، وحماية لمدخلات API.

## إضافة صور جديدة للمعرض

يعرض المعرض كل صورة عمل مرة واحدة، ويحتفظ بخانتين فارغتين للصور القادمة. لإضافة صورة جديدة، أضف ملفها إلى `public/img/` ثم أضف عنصرًا بمعرّف فريد في قائمة الصور داخل `public/ms.js`، وأضف المعرّف واسم الملف إلى خريطة الصور في `public/admin.js` حتى تظهر الصورة الصحيحة عند مراجعة تعليقاتها. لا تُضف الشعار أو صورة مستخدمة في قسم آخر إلى المعرض مرة ثانية.

## النشر على Vercel

تُقدّم ملفات `public/` الثابتة عبر Vercel؛ يعيد المسار `/admin` كتابة صفحة `admin.html` صراحةً، وتحوّل دالة `api/[...path].js` جميع طلبات `/api/*` إلى Express. اترك Framework وBuild Command وOutput Directory في إعدادات المشروع على الاكتشاف/القيم الافتراضية، وتأكد من عدم وجود إعداد نشر قديم يحصر البناء في `index.html` فقط. قبل أول طلب للـAPI:

1. اربط مستودع GitHub بمشروع Vercel واجعل مجلد المشروع هو Root Directory. استخدم إعداد **Other** أو الإعداد المكتشف تلقائيًا، ولا تضبط Output Directory على `public` لأنه قد يستبعد دالة API؛ اترك Build Command وOutput Directory على القيم الافتراضية.
2. جهّز قاعدة PostgreSQL مُدارة ومتاحة من Vercel، ثم أضف هذه المتغيرات في Vercel: افتح **Project → Settings → Environment Variables** وأضف القيم لكل من Production وPreview عند الحاجة:
   - `DATABASE_URL`: رابط اتصال PostgreSQL؛ استخدم رابطًا مجمّعًا (pooled) إذا كان مزود قاعدة البيانات يوفّره.
   - `ADMIN_EMAIL`: بريد دخول الإدارة.
   - `ADMIN_PASSWORD`: كلمة مرور قوية وفريدة بطول 14 حرفًا على الأقل.
   - `SESSION_SECRET`: قيمة عشوائية سرية لا تقل عن 32 حرفًا.
   - `PGSSL`: اضبطها على `true` فقط إذا كان مزود قاعدة البيانات يتطلب TLS.
3. أعد النشر بعد حفظ المتغيرات. افتح `/` للموقع و`/admin` للإدارة.

نجاح البناء وحده لا ينشئ قاعدة البيانات أو هذه الأسرار؛ من دون إعدادها لن تعمل الطلبات والتعليقات وتسجيل دخول الإدارة. لا تضع الأسرار في `vercel.json` أو ملفات الواجهة أو Git. راجع [ADMIN-SETUP.md](./ADMIN-SETUP.md) لإعداد الإنتاج والنسخ الاحتياطي.

## GitHub Pages

يوجد سير عمل GitHub Pages ينشر واجهة الموقع من `public/` ويجهّز صفحة الإدارة على `/admin/`. GitHub Pages يستضيف ملفات ثابتة فقط ولا يشغّل Express أو قاعدة PostgreSQL؛ لذلك يعرض صفحة الدخول لكنه لا يستطيع تسجيل الدخول أو حفظ الطلبات. لتشغيل الإدارة والنماذج استخدم نشر Vercel أعلاه، واضبط متغيرات قاعدة البيانات والأسرار على المشروع نفسه.
